# 행정정보 데이터베이스 표준화 지침
- 2008-11-25

## 제34조, (데이터요소의 명명 규칙)
### 2항 4호 
- 테이블의 이름은 1자리의 물리적 특성구분어, 1자리의 논리적 특성 구분어, 언더스코어('_'), 그리고 테이블에 해당하는 엔티티의 이름으로 구성
- 1. 물리적 특성 구분어 T는 테이블, V는 뷰, C는 클러스터, P는 파티션, E는 기타
- 2. 논리적 특성 구분어 N는 일반테이블, H는 이력 테이블, C는 코드테이블, T는 임시테이블, S는 통계테이블, E는 기타
- 3. 데이터웨어하우징(DW), 온라인분석프로세스(OLAP) 등의 경우, 차원을 나타내기 위한 D, 차원에 따른 사실 값을 나타내기 위한 F를 논리적 특성구분어로 사용
- 4. 하나의 엔티티가 다수의 테이블로 구현되는 경우, 엔티티의 이름, 일련번호를 테이블에 해당하는 엔티티의 이름으로 부여
- 6. 영문대문자를 사용하는 것을 원칙

# DB 초기화 스크립트 파일 규칙

## 파일 분리 원칙
- DB 초기화 스크립트(`db-init/*.sql`)는 **구조(Schema)**와 **데이터(Data)**로 분리하여 관리합니다.
- **구조(Schema) 파일**: `CREATE TABLE`, `ALTER TABLE` 등 데이터베이스 객체 정의를 포함합니다.
- **데이터(Data) 파일**: `INSERT INTO`, `UPDATE` 등 초기 데이터 삽입 및 수정을 포함합니다.

## 파일 명명 규칙
- 파일은 `init[N].[M]-[Description].sql` 패턴을 따릅니다.
- **`[N]`**: 도메인 또는 주요 실행 순서를 나타내는 번호 (예: `1` for user, `2` for nms).
- **`[M]`**: 하위 실행 순서. `1`은 구조(Schema), `2`는 데이터(Data)를 의미합니다.
- **`[Description]`**: 파일의 내용을 설명하는 이름 (예: `user-schema`).

### 실행 순서
- `docker-entrypoint-initdb.d`는 파일을 알파벳 순서로 실행합니다.
- 위 명명 규칙은 **스키마 파일이 항상 데이터 파일보다 먼저 실행되도록** 보장합니다.

### 예시
- `init1.1-user-schema.sql` (사용자 관련 테이블 생성)
- `init1.2-user-data.sql` (사용자 관련 초기 데이터 삽입)
- `init2.1-nms-schema.sql` (NMS 관련 테이블 생성)
- `init2.2-nms-data.sql` (NMS 관련 초기 데이터 삽입)
